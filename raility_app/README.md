# Raility · 도시철도 취약성 진단

> 지도 앱은 **지금 다니는 길**을 알려준다.
> Raility는 **그 길 위 어느 역 하나가 멈추면 돌아갈 수 있는지**를 알려준다.

2026년도 공공데이터 활용 공모전 — 분야 1(실제 구현 가능한 신규 웹/앱 서비스 개발) 출품작.
국가철도공단 공공데이터를 사용한다.

## 무엇이 다른가

기존 길찾기 서비스는 평시의 최단경로만 다룬다. 사고·공사·재난으로 한 역이 멈췄을 때
**내 경로가 우회 가능한지**는 어디서도 알려주지 않는다.

Raility는 출발–도착 경로를 구한 뒤 **경로 위의 역을 하나씩 그래프에서 제거하고 다시 탐색한다.**
경로가 사라지면 그 역을 **단일고장점(SPOF)** 으로 판정한다. 시장에 같은 기능을 제공하는
서비스가 없고, 계산에 필요한 것은 전부 공개된 공공데이터다.

## 화면

| 탭 | 내용 |
|---|---|
| **진단** | 출발·도착역 선택 → 취약도 등급(A–E), 소요시간, 정차역 수, 단일고장점 수. 경로 상세에 역별 "우회 불가" / "우회 시 +N분" 표시 |
| **지도** | 권역별 철도망을 좌표 기반 SVG로 렌더. 끊기면 망이 분리되는 구간·역을 적색으로 강조. 핀치 확대·드래그 지원 |
| **대전** | 대전 도시철도 1호선 전 구간 진단과 권역별 구조적 취약도(절점 비율) 비교 |
| **데이터** | 활용 공공데이터 목록, 분석 방법, 한계 |

## 대전권에 대한 발견

대전은 운영 중인 도시철도가 **1호선 단일 노선**이다. 망에 순환이나 병렬 경로가 없어
중간역 어느 하나가 끊기면 우회할 방법이 **구조적으로 존재하지 않는다.**

권역별 **절점 비율** — 절점은 제거하면 철도망이 둘 이상으로 쪼개지는 역이다.

| 권역 | 절점 / 역 | 비율 |
|---|---:|---:|
| 대전 | 20 / 22 | **91%** |
| 광주 | 18 / 20 | 90% |
| 대구 | 82 / 97 | 85% |
| 부산 | 80 / 141 | 57% |
| 수도권 | 198 / 661 | 30% |

판암→반석 전 구간 진단 결과 **중간역 20개 전부가 단일고장점**(등급 E)이다.
대전 도시철도 2호선(트램) 개통 시 이 지표가 어떻게 바뀌는지가 곧 투자 효과의 정량적 근거가 된다.

## 기술

- **의존성 0.** 외부 라이브러리·CDN·지도 타일을 쓰지 않는다. 지도는 역 좌표로 직접 그린 SVG다.
- **서버 0.** 최단경로·단일고장점 판정이 전부 브라우저에서 실행된다. 어떤 데이터도 외부로 나가지 않는다.
- **PWA.** 설치 가능하고 오프라인에서 완전히 동작한다.
- 진단 1회 계산: 역 1,094개·구간 1,344개 그래프에서 수십 ms.

```
index.html              앱 셸
assets/app.css          디자인 시스템 (라이트/다크, prefers-reduced-motion 대응)
assets/app.js           UI · 지도 렌더링
assets/graph.js         그래프 구성 · 최단경로 · SPOF · 절점 판정
assets/data.js          네트워크 데이터 번들 (build_app_data.py 생성)
manifest.webmanifest    PWA 매니페스트
sw.js                   서비스 워커 (오프라인 캐시)
test_graph.js           로직 검증 47건
_legacy/                이전 버전 보관
```

## 실행

```bash
# 정적 파일이면 되므로 아무 서버나 가능
cd raility_app
python -m http.server 8731
# → http://127.0.0.1:8731/index.html
```

`index.html`을 파일로 바로 열어도 동작한다(서비스 워커만 비활성).

### 데이터 다시 만들기

```bash
python build_app_data.py     # 프로젝트 루트에서 실행
```

`data/processed/`, `results/` 의 분석 산출물을 읽어 `assets/data.js` 를 생성한다.
표준 라이브러리만 사용한다.

### 검증

```bash
node raility_app/test_graph.js
```

데이터 무결성, 최단경로 정확성(연속성·대칭성), 역 차단 의미론, 대전 단일 노선 특성,
역 표기 병합, 환승 표기, 절점 판정(연결요소 증감 대조)까지 47건을 검사한다.

## 활용 공공데이터

전부 공공데이터포털(data.go.kr) 국가철도공단 제공 데이터다.

- 전국 도시철도 역사정보 — 역 위치·노선·환승 구분
- 전국 도시철도 노선정보 — 노선별 정거장 구성
- 전국 도시철도 운행정보 — 운행 순서·소요시간·운행 횟수
- 노선별 역간거리 (18개 노선)
- 노선별 환승정보 (15개 기관)
- 각 운영기관 역별 승하차실적 — 이용 규모

## 데이터 처리 시 확인한 사항

원본 데이터를 그대로 쓰면 결과가 왜곡되는 지점들이 있어 다음을 보정했다.
`build_app_data.py` 와 `assets/graph.js` 주석에 근거를 남겨 두었다.

1. **역명 표기 불일치.** 같은 역을 "신도림"(2호선)과 "신도림역"(경부선)처럼 다르게 적는다.
   그대로 두면 한 역이 둘로 쪼개져, 실제로는 불가능한 *닫힌 역에서의 환승*을 우회로로 인정해
   취약성을 실제보다 **낮게** 보고한다. 이름을 정규화해 병합하되 좌표 1.2 km 이내 조건을 함께 걸었다.
   50개 역 그룹이 해당한다.

2. **인접 구간의 노선 라벨 어긋남.** 운행 엣지 1,160개 중 112개(9.7%)가 양 끝 노드의 노선이 다르다
   (같은 이름의 다른 노선 노드에 인접이 붙었다). 역 단위 위상 자체는 옳아 SPOF 판정에는 영향이
   없으나 화면에 표시되는 노선명이 틀어진다. 구간마다 양쪽 역이 **공유하는** 노선을 골라 표시하도록 했다.

3. **주소 표기 누락.** 대구권 역 주소는 시도 접두어 없이 구 단위로 시작해 주소 기반 권역 분류가
   실패한다. 운영기관 → 좌표 순으로 판정하도록 바꿨다.

4. **고립 노드.** 짝이 되는 구간 없이 남는 역은 검색에는 떠도 경로가 나오지 않으므로 번들에서 뺀다.
   2026-08-04 그래프 재구축으로 인천공항 자기부상철도가 연결되면서 현재 판에서는 해당 노드가 없다.

## 한계

실시간 운행 상황, 열차 시각표, 버스 등 대체 수단은 반영하지 않는다.
물리적 선로 연결 구조만으로 판단한 결과다. 환승 소요는 210초로 일괄 가정했다.
