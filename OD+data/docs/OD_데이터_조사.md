## 1. 결론 요약 (2026-08-03 팀장 결정 반영: 경로 ② 메인)

> **국가철도공단 명의의 도시철도 OD(기종점 통행량) 데이터는 공공데이터포털과 레일포털 어디에도 존재하지 않는다. [확인]**
> 그러나 **타 기관(서울시/한국스마트카드) 명의의 수도권 지하철 역간 OD를 실제 다운로드하는 데 성공했다** — ① 서울시 정류장·역사별 출발지-도착지 정보(일별·시간대별, 최근 1주일치, 지하철 역간 29만 쌍/일·690만 통행/일), ② 서울시 지하철 역별 OD 샘플(1일치, 권종별). **R1 대응은 경로 ②(타기관 OD)를 메인으로 확정**하며, 공모전의 '공단 데이터 1건 이상' 요건은 공단 명의 노선·환승·역사 데이터로 충족한다. 운행시각표 빈도 가중치는 OD 미확보 구간(지방 도시권)의 보조·민감도 분석용으로 강등한다. 상세는 6장.

## 2. 국가철도공단 명의 OD 데이터 — 존재하지 않음

### 2-1. 공공데이터포털(data.go.kr) 검색 결과 [확인]

2026-08-03 기준 data.go.kr 데이터 목록 검색을 직접 조회한 결과:

| 검색어 | 결과 |
|---|---|
| `국가철도공단 OD` | **결과 없음** |
| `국가철도공단 통행` | **결과 없음** |
| `국가철도공단 승하차` | 승강장 이격거리, 교통약자 도우미 전화번호 등만 검색됨 (통행량 아님) |
| `국가철도공단 수송` | 에스컬레이터 현황 등만 검색됨 (통행량 아님) |

국가철도공단 명의 데이터셋은 역사정보·노선정보·시각표·편의/안전시설(화장실, 물품보관함, 스크린도어 등)·역위치·역간거리 CSV 중심이며, **OD·승하차 인원·수송실적 성격의 데이터는 1건도 없다.**

- 출처: https://www.data.go.kr/tcs/dss/selectDataSetList.do (키워드 "국가철도공단"으로 검색)

### 2-2. 레일포털(철도산업정보센터, data.kric.go.kr) Open API 전체 목록 [확인]

레일포털 Open API 목록(전 카테고리)을 직접 조회하여 **전체 36개 API를 전수 확인**했다. 카테고리는 열차이용정보(trainUseInfo), 안전정보(safetyInfo), 편의정보(convenientInfo), 교통약자정보(vulnerableUserInfo/handicapped) 등이며, **OD·통행량·승하차 인원 API는 없다.** 가장 근접한 것은 "역사별 혼잡도 정보(서울교통공사 평일 혼잡도)"(convenientInfo/stationCongestion) 정도다.

- 출처: https://data.kric.go.kr/rips/M_01_02/intro.do (Open API 목록, lcd=A~E 전 카테고리 조회)

### 2-3. 배경 [추정]

승하차·OD 데이터는 통상 각 도시철도 **운영기관**(서울교통공사, 부산교통공사 등)과 교통카드 정산 데이터를 다루는 기관(한국교통안전공단 STCIS, 티머니 등)이 보유·개방한다. 국가철도공단은 건설·시설 관리 기관이므로 수요 데이터를 개방하지 않는 것으로 보인다. 팀 계획서 R1의 전제("승하차·OD는 통상 각 운영기관/KTDB 소유")와 일치한다.

**그래프 노드 매핑 평가**

## 6. 결론 및 권고 (R1 대응 — 2026-08-03 팀장 결정: 경로 ② 메인)

1. **경로 ② (타기관 OD → 승객영향 분석의 핵심 데이터): 메인 경로 — 확정.**
   - **이미 확보 완료**: 수도권 지하철 역간 OD(서울시/한국스마트카드, 일별·시간대별, 2026-07-22~28 1주일치)가 `data/od/`에 있다. 단절 통행량·우회비용·첨두 취약성 분석을 이 데이터로 수행한다. 역사마스터(99.9% 매칭)로 공단 노선 그래프의 노드와 조인한다 (5-1절 참조).
   - **보강 신청(병행)**: ① 서울시 지하철 역별 OD 전체분(이메일 요청, 권종별·역명 기반), ② STCIS(지방 도시권 역간 OD의 유일한 경로 — 대전·부산·대구 확보 시 도시별 비교 챕터 강화). 절차는 `OD_신청_가이드.md`.
   - 지방 도시권은 OD 확보 전까지 승하차 데이터(부산·대구·대전·인천 확보 완료)로 **노드(역) 승객 가중치** 기반 영향 분석을 적용한다.
2. **공모전 요건 충족 구조**: '공단 데이터 1건 이상' 요건은 **국가철도공단 명의 도시철도 전체노선정보·역사별 환승정보·역사정보**(그래프 구축의 뼈대)로 충족한다. 요강상 복수 데이터 선택이 가능하므로, 논문 데이터 장에 "네트워크 구조 = 공단 데이터, 승객 수요 = 서울시/한국스마트카드 OD 보조 활용"으로 명시하면 된다.
3. **경로 ① (열차별 운행시각표 → 운행빈도 가중치): 보조·민감도 분석용으로 강등.**
   - 용도 재배치: (a) **OD 미확보 구간(대전·부산·대구 등 지방 도시권)의 엣지 서비스수준(운행빈도) 가중치**, (b) 수도권에서 OD 가중치 vs 빈도 가중치 결과 비교(민감도 분석) — 방법론 강건성 근거.
   - API 전용이므로 레일포털 인증키 발급 후 수집 (`API_신청_가이드.md`).
4. KTDB는 존(zone) 단위 OD라 역 단위 분석에 부적합 — 배경 수요 서술·검증용 보조로만.
5. 논문 서술 지침: 수도권은 "역간 OD 기반 승객영향(단절 통행량·우회비용·첨두/비첨두)", 지방은 "승하차 기반 노드 가중 근사(+운행빈도 엣지 가중)"로 이원화하고, 한계 절에 지방 역간 OD 미공개와 카드 태그 OD의 경로배정 가정(환승 경유 미포함)을 명시할 것.
